## 一、项目概述

### 1.1 项目定位

「墨匣」是一个人机共创的创作工作台，帮助用户把一个灵感打磨成完整的作品。支持三种创作模式：

| 模式 | 目标平台 | 核心特点 |
|------|---------|---------|
| 知乎网文 | 知乎盐言故事 | 短篇情绪流，开头钩子 + 反转爽点 |
| 漫剧剧本 | AI 漫剧/短剧制作 | 剧本 + 视觉设定 + 连续性锁 |
| 易次元文游 | 易次元文字冒险游戏 | 主线 + 多支线 + 选项节点 + 立绘标注 |

### 1.2 核心使用流程

```
灵感 → AI 补全大纲 → 生成内容 → 用户观察/选择/调整 → 完整作品
```

用户是创作的导演，AI 是执行助手。每一步都落盘成文件，用户在节点上审核、修改、再继续。

### 1.3 设计来源

本项目的工作流和机制主要借鉴以下开源项目（均为 MIT / Apache-2.0 协议，可自由复用）：

| 借鉴项目 | 复用内容 |
|---------|---------|
| oh-story-claudecode | 网文五阶段流程、10 大题材包、去 AI 味三层质检、文件记忆结构 |
| drama-skills | 漫剧剧本格式、视觉设定、连续性锁机制、分镜三段式 |
| chinese-novelist-skill | 「灵感→大纲」的三层问答思路 |

## 二、整体架构

### 2.1 项目形态

**阶段一（当前）**：Skill 包形式，在 Trae / Claude Code 中通过 `/墨匣` 调用。  
**阶段二（未来）**：验证流程跑通后，考虑封装为独立 Web 应用。

选择 Skill 包先行的原因：
1. 零开发成本，立即可用
2. 可直接复用 oh-story 和 drama-skills 的成熟工作流
3. 先验证人机共创流程在三个领域是否都跑得通，再决定是否界面化

### 2.2 模式关系：混合模式

- **默认独立**：每个作品只选一种模式，有独立的文件结构
- **支持跨模式改编**：可从网文改编成漫剧或文游（复制设定 + 角色，按新模式生成其余文件）

### 2.3 实施优先级

```
A. 知乎网文（最成熟，先验证底层流程）
    ↓
B. 漫剧剧本（在网文流程上加视觉标签和分镜）
    ↓
C. 易次元文游（在网文流程上加分支节点和多结局）
```

### 2.7 跨模式改编流程

当用户说"把这篇网文改成漫剧/文游"时：
1. 读取源作品的 `设定.md` + `角色.md`
2. 复制到新作品目录
3. 按目标模式的结构生成其余文件
4. 漫剧：正文 → 剧本（加视觉标签）+ 视觉设定（提取识别锚点+连续性锁）
5. 文游：正文 → 主线大纲（标注分支点）+ 支线设计

## 三、知乎网文模式详细设计

### 3.1 模式定位

- 目标平台：知乎盐言故事
- 篇幅：短篇（8000-15000 字）
- 核心特点：情绪驱动、开头钩子、反转/爽点、短平快节奏

### 3.2 五阶段工作流

```
阶段1：灵感输入 → 阶段2：AI补全大纲 → 阶段3：生成正文 → 阶段4：去AI味 → 阶段5：成稿交付
```

### 3.3 阶段 1：灵感输入

**触发**：`/墨匣-网文` + 灵感

**交互**：AI 确认两个问题
1. 目标情绪：爽感释放 / 意难平 / 反转震撼 / 治愈温暖 / 细思极恐 / 共鸣感动
2. 题材方向：世情打脸 / 甜宠 / 追妻火葬场 / 悬疑 / 总裁豪门 / 宅斗宫斗 / 双男主 / 复仇打脸 / 民俗怪谈 / 沙雕脑洞

### 3.4 阶段 2：AI 补全大纲

**AI 动作**：
1. 读取对应题材包的写法、钩子、情绪烈度
2. 基于灵感生成 **3 个不同方向**的大纲方案
3. 每个方案包含：故事核、人物、反转点、付费点设计

**用户确认后落盘**：`设定.md` + `角色.md` + `大纲.md`

**大纲格式**：
```markdown
# 大纲 · 作品名

## 章节规划

### 第1章 · 章名
- 目标：本章要完成什么
- 冲突：核心矛盾
- 转折：关键反转
- 章尾钩子：留下什么悬念
```

### 3.5 阶段 3：生成正文

**触发**：用户说"开始写正文"

**AI 动作**：
1. 读取 `设定.md` + `角色.md` + `大纲.md`
2. 按大纲逐章生成正文
3. 每章生成后**停下等用户确认**，不自动连写

**用户选项**：确认继续 / 重写本章 / 局部修改 / 先放着

**落盘**：`正文.md`（追加模式，每章用 `---` 分隔）

### 3.6 阶段 4：去 AI 味

**三层质检**（借鉴 oh-story 的 story-deslop）：

| 层级 | 检查内容 |
|------|---------|
| 表达层 | 电报体、短碎句、机械复现、AI 高频词（仿佛/好像不超过 10 处） |
| 用笔层 | 场景详略、细节功能、无用描写 |
| 故事层 | 行为因果、人物动机、知情顺序 |

### 3.7 阶段 5：成稿交付

**产出**：合并后的完整正文 + 字数统计 + 知乎盐言投稿格式优化

### 3.8 质量门禁

| 检查项 | 标准 |
|--------|------|
| 总字数 | 8000-15000 |
| 开头钩子 | 前 3 句有冲突/悬念 |
| AI 高频词 | "仿佛""好像"不超过 10 处 |
| 章节数 | 与大纲一致 |
| 每章字数 | 2000-3000 |

## 四、漫剧剧本模式详细设计

### 4.1 模式定位

- 目标：产出可用于 AI 漫剧/短剧制作的剧本 + 视觉设定
- 核心差异：相比网文，多了**视觉标签**和**连续性锁**
- 简化策略：默认只维护 2 份核心文档（剧本 + 视觉设定），分镜/提示词按需生成

### 4.2 四阶段工作流

```
阶段1：故事开发 → 阶段2：剧本写作 → 阶段3：视觉设定 → 阶段4：分镜+提示词（按需）
```

### 4.3 阶段 1：故事开发

**两种入口**：
- 从灵感出发：同网文模式，AI 发散 3 个方向
- 从网文改编：读取已有网文作品，改编成分集

**确认制作形态**：写实漫剧 / 二次元动漫风 / 水墨国风 / Q 版可爱风

**产出**：分集地图

**分集地图格式**：
```markdown
# 分集地图

## EP001 · 集名
- 进入状态：...
- 开场：...
- 当集追求：...
- 阻力：...
- 转折：...
- 当集结果：...
- 信息释放：...
- 集尾钩子：...
- 下集继承：...
```

### 4.4 阶段 2：剧本写作

**剧本格式**：
```markdown
# EP001 · 集名

## EP001-SC001 内 · 地点 · 时间

动作叙述...

[OS] 角色：画外音台词

[VO] 角色：内心独白

角色（表演提示）：台词

[画面文字] 屏幕显示的文字

[SFX] 音效

[连续性] 跨场状态交接
```

**生产标签说明**：

| 标签 | 含义 |
|------|------|
| `[VO]` | 角色内心独白（画外音） |
| `[OS]` | 画外音（画面外的人说话） |
| `[SFX]` | 音效 |
| `[画面文字]` | 屏幕上显示的文字 |
| `[连续性]` | 跨场状态交接 |

### 4.5 阶段 3：视觉设定

**AI 动作**：从剧本提取人物、场景、道具，生成视觉设定

**核心机制：识别锚点 + 连续性锁**

**视觉设定格式**：
```markdown
# EP001 视觉设定

## 人物 · 江晨
- 22 岁男性，清瘦长脸，高眉骨，短寸黑发
- 造型：松枝绿军装常服
- 识别锚点：长脸、高眉骨、深眼窝、短寸、绷直肩背
- 连续性锁：LOCK-JIANGCHEN-DRESS《江晨军装》
  · 锁面：pine-green military uniform
  · 出现镜头：全 EP001

## 地点 · 副团长办公室
- 浅橡木办公桌，背后蓝色文件夹书柜
- 识别锚点：浅橡木桌、蓝色文件夹书柜

## 道具 · 玻璃泡茶杯
- 双层玻璃直身杯，冷茶沉底
- 识别锚点：双层玻璃杯身、沉底绿茶叶
```

**连续性锁的作用**：每个角色/重要道具配一条英文短语锁，后续所有分镜提示词都带上这条锁，保证跨镜/跨集造型一致。

### 4.6 阶段 4：分镜 + 提示词（按需）

**分镜格式**：
```markdown
# EP001 分镜

## SHOT-EP001-001 · 镜头名
- 来源：EP001-SC001
- 时长：3s
- 景别：大特写
- 起点：右手攥着茶杯，指节发白
- 唯一动作：哄笑声起，手又攥紧一分
- 终点：指节攥到发白，茶面在抖
- 视觉依据：人物「江晨」、道具「玻璃泡茶杯」

### 冻结关键帧提示词
> 9:16 vertical extreme close-up of a hand with pine-green military uniform cuff...
```

**分镜三段式**：起点 → 唯一动作 → 终点（一镜一事）

### 4.7 从网文改编漫剧

1. 读取网文的 `设定.md` + `角色.md` + `正文.md`
2. AI 把正文拆解成分集地图
3. 文字叙述转成场景+对白+[VO]/[OS]标签
4. 从角色描述提取视觉识别锚点，生成连续性锁
5. 产出 `剧本.md` + `视觉设定.md`

## 五、易次元文游模式详细设计

### 5.1 模式定位

- 目标：易次元文字冒险游戏剧本
- 核心模型：**一条主线 + 多条支线 = N 个线性故事**
- 关键机制：选项节点、多结局、立绘/CG 标注
- 复用基础：主线和每条支线都复用网文的「设定→大纲→正文」流程

### 5.2 五阶段工作流

```
阶段1：世界观+主线 → 阶段2：支线设计 → 阶段3：分支写作 → 阶段4：立绘/CG标注 → 阶段5：整合导出
```

### 5.3 阶段 1：世界观 + 主线

**确认两个问题**：
1. 主线长度：短篇（5-10章）/ 中篇（10-30章）/ 长篇（30章+）
2. 支线数量：2-3条 / 4-6条 / 先做主线

**AI 动作**：
1. 生成主线大纲（3 个方向选 1）
2. 在主线大纲中标注**分支点**位置

**主线大纲格式（带分支点）**：
```markdown
# 主线大纲 · 读心者

## 第1章 · 意外的能力
- 目标：主角获得读心能力
- 分支点：是
- 选项：
  - A. 告诉室友 → 支线A · 信任危机
  - B. 隐瞒独自探索 → 主线第2章
  - C. 去找心理医生 → 支线C · 求医之路
```

### 5.4 阶段 2：支线设计

**选项节点.md 格式**：
```markdown
# 选项节点

## 分支点 1 · 第1章末尾

**触发条件**：主角获得读心能力后

**选项**：
- **A. 告诉室友**
  - 跳转：支线A · 信任危机
  - 解锁条件：无
  - 好感度影响：室友 +10

- **B. 隐瞒并独自探索**
  - 跳转：主线第2章
  - 解锁条件：无
```

**支线大纲格式**：
```markdown
# 支线A · 信任危机

## 基本信息
- 入口：第1章选项A
- 结局类型：BE（坏结局）
- 预计章节：3 章

## 章节规划
### 支线A-第1章 · ...
```

**结局类型**：HE（好结局）/ BE（坏结局）/ TE（真结局）/ NE（普通结局）

### 5.5 阶段 3：分支写作

- 主线和支线**独立写作**，每条线复用网文的逐章生成流程
- AI 检查**共享角色的一致性**（角色在各线中性格不矛盾）
- 支线入口章标注承接关系：`> 【承接】主线第1章选项A：...`

### 5.6 阶段 4：立绘/CG 标注

**行内标注格式**：
```markdown
## 第1章 · 意外的能力

[BG: 宿舍·白天]
[BGM: 日常轻松]

[立绘: 室友·惊讶]
室友：你说什么？你能听到别人在想什么？

[立绘: 主角·犹豫]
主角：嗯……我也不知道怎么回事。

[CG: 主角捂住耳朵痛苦]
[SFX: 耳鸣]
主角：（好多声音……脑子里全是别人的想法……）
```

**标注标签**：

| 标签 | 含义 | 示例 |
|------|------|------|
| `[BG: 地点·时间]` | 背景图 | `[BG: 宿舍·白天]` |
| `[BGM: 音乐名]` | 背景音乐 | `[BGM: 悬疑紧张]` |
| `[立绘: 角色·表情]` | 角色立绘 | `[立绘: 室友·惊讶]` |
| `[CG: 描述]` | 剧情插图 | `[CG: 主角捂耳朵痛苦]` |
| `[SFX: 音效]` | 音效 | `[SFX: 耳鸣]` |
| `[转场: 类型]` | 转场效果 | `[转场: 淡入]` |

**额外产出**：立绘清单、CG 清单（供画师参考）

### 5.7 阶段 5：整合导出

**产出**：
1. 完整剧本（所有线合并，带标注）
2. 选项节点总表（分支点→选项→跳转映射）
3. 立绘/CG/BGM 清单
4. 结局列表

**结局列表示例**：
```markdown
| 结局 | 来源支线 | 类型 | 触发条件 |
|------|---------|------|---------|
| 信任崩塌 | 支线A | BE | 第1章选A |
| 真相大白 | 支线B | HE | 第5章选A且智力≥60 |
```

| 复用网文流程 | — | ✅ 改编 | ✅ 每条线都是网文 |

## 七、实施计划

### 阶段 A：知乎网文 Skill 包（优先）

**目标**：跑通「灵感→大纲→正文→去味→交付」全流程

**任务**：
1. 创建 `moxia/` Skill 包目录结构
2. 编写 `moxia-router/SKILL.md`（路由 + 灵感输入）
3. 编写 `moxia-webnovel/SKILL.md`（五阶段工作流）
4. 从 oh-story 提取 10 大题材包到 `moxia-shared/`
5. 编写去 AI 味三层质检规则
6. 用真实灵感试写一篇，验证流程

### 阶段 B：漫剧剧本 Skill 包

**目标**：在网文流程基础上加视觉标签和连续性锁

**任务**：
1. 编写 `moxia-drama/SKILL.md`（四阶段工作流）
2. 编写剧本格式规范（场景标题 + 生产标签）
3. 编写视觉设定规范（识别锚点 + 连续性锁）
4. 编写分镜格式规范（三段式 + 冻结关键帧）

## 八、风险与约束

| 风险 | 应对 |
|------|------|
| AI 生成的网文质量不稳定 | 三层去 AI 味质检 + 人工审核门禁 |
| 漫剧角色造型跨镜不一致 | 连续性锁机制（英文短语锁定） |
| 文游支线之间角色性格矛盾 | AI 跨线一致性检查 |
| 易次元导入格式不明确 | 先产出结构化剧本，人工搬运；后续研究导入规范 |
| 提示词 token 消耗大 | 每次只读取当前任务必需的文件，不整读全书 |
